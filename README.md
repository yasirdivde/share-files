# ShareFiles

> Direct peer-to-peer file sharing between devices. No servers, no accounts, no uploads.

[![Live Demo](https://img.shields.io/badge/demo-live-brightgreen)](https://yasirdivde.github.io/share-files/)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Made with WebRTC](https://img.shields.io/badge/Made%20with-WebRTC-orange)](https://webrtc.org/)
[![PWA](https://img.shields.io/badge/PWA-installable-purple)](https://web.dev/progressive-web-apps/)

**ShareFiles** is a lightweight, browser-based file transfer tool that connects two devices directly through WebRTC. Files are streamed in encrypted chunks over a peer-to-peer data channel — they never touch any server. Just open the site on both devices, pair them with a 6-character code or QR scan, and transfer.

## ✨ Features

- **Direct P2P transfer** — files travel device-to-device via WebRTC, never through a server
- **6-character pairing code** — quick and human-friendly (e.g. `A3K9ZP`)
- **QR code pairing** — one-tap connect for mobile devices
- **Multi-file support** — select several files at once; they're auto-bundled into a zip
- **Memory-efficient streaming** — files are read and sent in 64 KB chunks with flow control, and received into a single preallocated buffer (no array-of-chunks overhead)
- **Live progress** — real-time percentage, speed (EMA-smoothed), and ETA
- **Installable PWA** — add to home screen on mobile or install on desktop
- **Offline-ready** — service worker enables reload without connectivity
- **Mobile-first responsive UI** — designed for phone-to-PC or phone-to-phone workflows
- **Zero backend** — pure static hosting; no server to maintain

## 🚀 How It Works

```
┌──────────┐                        ┌──────────┐
│  Sender  │                        │ Receiver │
└────┬─────┘                        └────┬─────┘
     │  1. Picks files                   │
     │  2. Generates 6-char code         │
     │  3. Waits for connection          │
     │                                   │
     │  4. Enters code / scans QR        │
     │◄──────────────────────────────────┤
     │                                   │
     │  5. WebRTC handshake via STUN     │
     │◄─────────────────────────────────►│
     │                                   │
     │  6. Direct P2P data channel open  │
     │◄─────────────────────────────────►│
     │                                   │
     │  7. META → ACK → 64KB chunks → DONE
     │──────────────────────────────────►│
     │                                   │
     │                       8. Blob → download
```

1. **Sender** picks files and gets a 6-character peer ID (generated by PeerJS).
2. **Receiver** enters the code; PeerJS brokers the initial handshake using public STUN servers.
3. Once connected, a **direct WebRTC data channel** opens — no relay.
4. Files are streamed as 64 KB binary chunks with **buffer-aware flow control** (`bufferedAmountLowThreshold` at 1 MB) to avoid overwhelming the connection.
5. Receiver preallocates a single `Uint8Array` of the incoming size, fills it by offset, and wraps it in a Blob on completion.

## 🛠 Tech Stack

| Layer | Technology |
|-------|------------|
| Language | Vanilla JavaScript (ES modules) |
| P2P transport | [WebRTC](https://webrtc.org/) via [PeerJS](https://peerjs.com/) |
| Zip bundling | [JSZip](https://stuk.github.io/jszip/) |
| QR generation | [qrcodejs](https://github.com/davidshimjs/qrcodejs) |
| QR scanning | [html5-qrcode](https://github.com/mebjas/html5-qrcode) |
| Styling | [Tailwind CSS](https://tailwindcss.com/) (self-hosted build) |
| Icons | [Font Awesome Free](https://fontawesome.com/) (self-hosted) |
| Font | [Inter](https://rsms.me/inter/) (self-hosted) |
| Hosting | [GitHub Pages](https://pages.github.com/) |

All dependencies are self-hosted inside `docs/` — the deployed site makes **zero external CDN requests**.

## 🧑‍💻 Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) 18+ (LTS recommended)
- A modern browser (Chrome, Edge, Firefox, or Safari — any recent version)

### Installation

```bash
git clone https://github.com/yasirdivde/share-files.git
cd share-files
npm install
```

### Build the CSS

```bash
npm run build:css
```

Outputs `docs/css/tailwind.css` (minified).

### Run locally

Any static server pointed at `docs/` works. Two easy options:

**Using VS Code:** install the *Live Server* extension, right-click `docs/index.html` → **Open with Live Server**.

**Using Python:**
```bash
cd docs
python -m http.server 5500
```
Then visit `http://localhost:5500`.

> ⚠️ **Do not open `docs/index.html` directly via `file://`** — ES modules require a proper HTTP origin.

## 🚢 Deployment

Hosted on **GitHub Pages**, serving from the `/docs` folder of the `main` branch.

### To deploy your own copy

1. Fork this repository.
2. Push to `main`.
3. Repo → **Settings → Pages** → **Source: Deploy from a branch** → **Branch: `main`** → **Folder: `/docs`** → **Save**.
4. Wait ~60 seconds; your site is live at `https://<your-username>.github.io/share-files/`.

## ⚠️ Limitations

- **300 MB max per transfer** — imposed by `MAX_SIZE_BYTES` in `fileManager.js` to keep memory usage sane.
- **STUN-only** — no TURN server is configured. This works for most home/office networks but **fails on symmetric NATs** or heavily restricted corporate networks where a relay would be required.
- **Both peers must be online simultaneously** — it's a live P2P connection, not a mailbox.
- **Same-network recommended** — for best speeds, both devices should be on the same Wi-Fi or LAN.
